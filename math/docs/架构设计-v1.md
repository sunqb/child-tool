# 审题雷达 · 架构设计 v1

纯静态单页工具，无后端、无构建。延续仓库约定：ES5、IIFE、`textContent` 渲染（禁 innerHTML）、数据走 `Store.*` 命名空间、localStorage 按工具前缀隔离（本工具前缀 `math.`）。

## 1. 文件与职责

```
math/
  index.html          家长单页（配置→预览→打印→历史变式）
  js/generator.js     出题引擎：纯函数、无 DOM、无 Store 依赖
  js/store.js         配置与历史卷持久化（localStorage）
  data/problems.json  题模板库（30 个，v1）
  tools/selfcheck.js  node 批量自检脚本（开发期，不部署）
  design/PRD.md       产品文档
  docs/架构设计-v1.md  本文档
```

依赖方向：`index.html → store.js / generator.js / problems.json`；generator 不依赖 store。

## 2. 题模板 schema（data/problems.json）

选题目录树（`meta.catalog`）：学科 `subjects` → 教材版本 `versions` → 年级 `grades` → 单元 `units` → 章节 `units[].chapters`，逐级以 `subjectId`/`versionId`/`gradeId` 挂靠。配置页按此五级级联渲染（同 dictation 手法）；单元、章节为多选，章节按选中单元分组展示。catalog 缺失时页面兜底为「单学科/通用版本/通用年级/无章节」。

模板字段：

```json
{
  "id": "T001",                    // 唯一，T + 三位序号
  "unit": "division",              // volume | division | strategy | average（mixed 预留）
  "chapter": "d-avg",              // 所属章节 id，见 meta.catalog 对应单元的 chapters
  "type": "standard",              // standard | distractor（多余条件）| supply（补条件）
  "skill": ["condition", "bridge"],// condition 关系词 hidden 隐藏条件 distractor 多余
                                    // supply 补条件 bridge 搭桥 unit 单位换算 steps 一两步判别
  "level": 2,                      // 1 基础 2 进阶 3 挑战
  "story": "超市运来{n1}箱酸奶，每箱{n2}盒，平均分装到{n3}个货架上。",
  "question": "每个货架放多少盒？",
  "params": { "n1": [3, 9, 1] },   // 变量: [min, max, step]，闭区间
  "calc": { "total": "{n1}*{n2}", "ans": "div({total}, {n3})" },
  "constraints": ["mod({total}, {n3}) == 0", "{ans} >= 10"],
  "segments": [                    // 逐段标注 story 的切分，**拼接必须等于 story**
    { "t": "超市运来{n1}箱酸奶", "type": "condition" },
    { "t": "，每箱{n2}盒", "type": "condition" },
    { "t": "，平均分装到{n3}个货架上", "type": "condition" }
  ],
  "relations": ["平均"],           // story+question 中的关系词（讲评页下划线；自检按两段文本匹配）
  "table": { "known": ["{n1} 箱", "每箱 {n2} 盒"], "ask": "每个货架 ？ 盒" },
  "bridge": {                      // 一步题为 null，渲染为「一步还是两步」判别
    "ask": "要求每个货架放多少盒，先要算出",
    "choices": ["酸奶总盒数", "箱数", "货架层数"],
    "answer": 0
  },
  "steps": ["{n1} × {n2} = {total}（盒）", "{total} ÷ {n3} = {ans}（盒）"],
  "answer": "{ans} 盒",
  "tip": "「平均分装到」= 总数 ÷ 份数。"   // 讲评页审题小锦囊
}
```

distractor 型：`segments` 含 `{ "type": "distractor" }` 段（该段的参数变量不进 calc）。

supply 型增加：

```json
"supply": {
  "choices": ["一共装了{n0}瓶", "…干扰项…", "…干扰项…"],
  "answer": 0,                     // 正确选项下标
  "why": "要求每瓶装多少毫升，必须知道总量和瓶数。总量有了，缺瓶数。"
}
```

`{n0}` 是补充进来的参数，参与 calc 与 steps。supply 型的 `table.known` 只放题面已有的条件；`table.supplyRow`（如 `"书一共 {n0} 本（补上的条件）"`）是补上后的表格行，**只在讲评页展示**，练习页的表格不出现（否则泄题）。

条件答案（可选，用于「带的钱够吗」这类结果不唯一的题）：

```json
"answers": [
  { "when": "{diff} > 0",
    "answer": "不够，还差 {diff} 元",
    "steps": ["{n2} ÷ {n1} = {per}（元）", "…", "带 {n4} 元 < 要用 {cost} 元，还差 {diff} 元"] },
  { "when": "1",
    "answer": "够，还剩 {rest} 元",
    "steps": ["…同上…", "带 {n4} 元 > 要用 {cost} 元，剩 {rest} 元"] }
]
```

- `when` 按声明顺序求值，第一个非 0 的分支生效：其 `answer` 覆盖 `tpl.answer`，`steps` 给了就整体覆盖；全不匹配视为实例化失败（触发重试）
- 约束必须保证各分支都真实可达；自检断言带 `answers` 的模板 100 次实例化至少出现 2 种答案
- distractor 模板约束惯例：多余条件的参数不得与有效参数撞值（如 T006 的 `{n0} != {n1}`、`{n0} != {n3}`），数值巧合会削弱「找多余条件」的训练价值

## 3. 约束与计算 DSL

generator 内置极简表达式求值器（递归下降，**不用 eval**）：

- 字面量：数字；变量引用（实例化时先做 `{var}` 字符串替换再求值）
- 运算符：`+ - * / %`（`/` 为实数除法）、比较 `== != > < >= <=`（产出 1/0）
- 括号；函数：`div(a,b)` 整除取商、`mod(a,b)` 取余、`min(a,b)`、`max(a,b)`

求值规则：`calc` 按 JSON 声明顺序求值（后面的可引用前面的）；`constraints` 每条结果必须非 0；实例化时随机参数（min/max/step 闭区间均匀取值），最多重试 200 次，全部失败返回 null（组卷时跳过换下一模板，**保证永不死循环**）。

## 4. 实例与历史卷 schema

`Generator.make()` 产出的卷：

```json
{
  "id": "s_ab12cd", "no": 3, "date": "2026-10-29",
  "config": { "level": "mix", "scaffold": "A", "withReview": true },
  "source": null,                  // 或 { "variantFrom": 2 }（由第 2 卷错题生成的变式卷）
  "problems": [ /* 实例数组 */ ]
}
```

实例 = 模板的**全量文本快照**（story/question/table/bridge/steps/answer/tip/segments/relations/supply 全部替换为具体数字后的结果；带 `answers` 的模板，steps/answer 取命中分支的文本）+ `tplId` + `params` + `marked`（null 或 true）。存快照的目的是：题库后续修改不影响旧卷重印与讲评；`params`+`tplId` 供变式重练定位模板。

变式卷的 `config.scaffold` 继承出处分卷（错题在什么档位做错的，就在什么档位重做；跨卷合并错题的变式沿用当前配置档位），`level`/`withReview` 取当前配置。

## 5. Store 契约（localStorage `math.` 前缀）

| 键 | 内容 | 默认值 |
|---|---|---|
| `math.config` | `{ subject, version, grade, units, chapters, level, scaffold, count, withReview }` | 数学 / 苏教版 / g4s / 全单元 / {} / mix / A / 5 / true |
| `math.sheets` | 卷数组（旧→新），上限 30，FIFO | `[]` |
| `math.no` | 卷号计数器 | 0 |

- `config.get()`：默认值合并 + 枚举校验（units ⊆ 已知单元、level/scaffold 枚举、count ∈ [3,10]；chapters 仅保留已知单元的字符串数组）
- `chapters` 语义：`unitId -> [chapterId]`，缺键 = 该单元全部章节，空数组 = 明确不选任何章节；与 catalog 的深层对齐（单元/章节随题库增删失效时逐级回退）在页面端 `normalizeSelection()` 做，同 dictation 的选择链路手法
- `Generator.make()` 过滤顺序：unit ∈ cfg.units → chapter ∈ cfg.chapters[unit]（若给出）→ level 匹配
- `sheets.add(sheet)`：补 id/no/date 后追加，超 30 卷丢最旧
- `sheets.get(id)` / `sheets.list()` / `sheets.mark(id, index, marked)` / `sheets.remove(id)`
- localStorage 不可用时内存兜底（同 dictation 手法）

## 6. 打印生命周期

复用 wrongbook 趟过的方案：

- 所有打印规则集中在一个 `<style media="print">` 块：`@page { size: A4 portrait; margin: 12mm }`；`body > *:not(#print-sheet) { display:none !important }`；`#print-sheet { display:block; color:#000 }`
- 题块 `.mq`、讲评块 `.mr` 均 `break-inside: avoid; page-break-inside: avoid`（双写保兼容）
- 讲评节 `page-break-before: always` 独立成页
- 题目行高 1.9em 供笔圈（圈划空间与密度折中）；不依赖背景色（黑白安全），标记语义用加粗/下划线/删除线/序号
- 密度实测（96dpi 换算 mm）：A/B 级题块 65–93mm ≈ 每页 3 题，C 级约 70mm = 每页 4 题。为此做的三个取舍：补条件三候选项排一行；「④ 算一算」编号并入首条算式线；表格行高 6mm（空行供孩子填写）
- 「第一步/第二步」提示线只印在 steps ≥ 2 的题上（14 个单步模板不印，避免误导）
- 讲评块编号与练习卷面严格一致：标准 ②列 ③想 ④算；补条件 ②补 ③列 ④算（无③想）
- 纯文本无图片：无 decode/objectURL 生命周期
- iPhone UA 检测：禁用打印按钮 + 常驻提示「请在电脑端打开本页打印」
- **调试**：`?debug=print` 把打印样式块的 `media` 属性切为 `all`，屏幕上直接检查卷面排版（node_repl / 截图验证用）

## 7. 质量保障

- `tools/selfcheck.js`（node 运行，不部署不入运行时）：先校验 catalog（模板 unit/chapter 归属、章节 id 唯一、章节下无空挂），再对每个模板实例化 100 次，断言：
  1. 约束全部通过、calc 结果均为有限数、该为整数处为整数
  2. `segments` 拼接 === `story`（替换后）
  3. `relations` 中每个词都能在 story 或 question 文本中找到
  4. supply.choices[answer] 替换后不含未解析的 `{`
  5. 带 `answers` 的模板，100 次内至少出现 2 种答案（条件分支真实可达）

已知取舍（v1 记录，不修）：T017 约束保证「升的那瓶」恒多（训练点是单位换算而非比较方向）；T018 因 `mod(total,1000)==0` 参数空间受限，答案只有 1/2/3 升三种。v2 扩参数集。
- 浏览器端 `?debug=print` 人工核对排版（A/B/C 脚手架 × 含/不含讲评页 × 3 题/10 题）
